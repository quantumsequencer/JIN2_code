# SGMO2 Control

SGMO2 0.2.0向けのGateway接続UIです。前回のtestの濃紺・シアンの画面を引き継ぎ、
個別工程と一括準備、リアルタイムグラフをまとめています。

## 起動

このPCのtest2専用環境は準備済みです。
IDEが旧testのPythonを選んでいても、main.pyの直接実行時はtest2/.venvへ自動で切り替えます。

- `StartUI.bat`：Gateway接続モード。起動だけでは接続・装置操作しません。
- `StartDemo.bat`：従来のローカルデモ。装置に接続せず波形・工程を再現します。

別環境で準備する場合（Windows / Python 3.12以上、メーカー推奨は3.13以上）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

## Gatewayと接続して操作する

通常は新UIの「Gatewayを起動して接続」を押すだけで、同梱Gatewayを起動し、
保存済みCOM設定で接続できます。同じ場所のGatewayが起動済みなら再利用します。
通信ポートもGatewayのconfig.jsonから読み取ります。20秒以内に接続できなければ理由確認を案内します。
初回・COM番号変更時のみGatewayでポートを選択し、正常終了して設定を保存してください。
新UIの保存値表示はsettings.jsonの値であり、現在のCOM接続状態ではありません。
Gatewayは新UIを閉じた後も残るため、最後にGatewayも正常終了してください。

手動で起動・接続する場合：

1. `SGMO2_original/JinGateway-0.2.0.09030/JinGateway.exe`を起動。
2. GatewayでHost / Debug / Logを選択。まずは3つとも`Stub`で確認できます。
3. Stubでは`Tools > Stub Host Port`からData Typeを測定データ種別にし、Startでデータ生成。
4. `StartUI.bat`を起動し、通常は受信55555・送信55556のまま「Gatewayに接続」。
5. Gateway接続後、`JinSettings`内の設定txtを選び、内容確認→「設定を装置へ適用」。Host待ちでも操作できます。
6. 「準備をまとめて実行」または各工程の「実行」。チップ装着で確認待ちになります。
7. 準備完了後、Hold Gap開始→測定停止。
8. 「リセット」は工程停止・Bias 0・EP 0・サンプリング停止の順で終了処理を行います。終了処理ではサンプリングを再開せず、ゼロ点移動も行いません。
9. UIの「終了」でも、操作済みなら終了処理を確認してから閉じます。その後Gatewayを終了します。

異常停止処理中の「終了」「終了処理して切断」は、現在の停止応答を待って終了処理へ進みます。
`sv_info_sender stop` の `Stop error : -3` はメーカーコードの `API_RUNNING` に対応するため、成功扱いにせず、Debugプロンプト確認後に0.5秒間隔で最大3回再試行します。
終了処理中は確認済みの項目を上部に表示します。失敗・タイムアウト時は接続とUIを保持します。「終了処理して切断」で再試行できます。「終了」では「終了処理を再試行」「UIのみ終了」「キャンセル」を選べます（初期選択はキャンセル）。UIのみ終了は装置・Gatewayの停止を行わないため、装置状態はGatewayで確認してください。受信停止だけでは装置の停止成功とは判定しません。

実機の準備・チップ装着・電源操作はSGMO2_manualの手順に従います。
CommandPanel / MeasurementWizardなど、他の操作Clientと同時にコマンド送信しないでください。
通信プロトコルに要求IDがなく、他Clientの応答を区別できません。

## 状態表示とデータ保存

- 接続はZeroMQの2つのソケットで判定し、Host受信状態は別に表示します。
- データ受信前も設定適用・初期化が可能です。初期化のLow測定開始コマンドで送信を開始します。
- Debug / Logは「受信実績」を表示します。COM番号・実機かStubか・記録状態はGateway側で確認します。
- 電流は受信Data TypeからLow 10 kHz / High 10・50・100 kHzを判定します。
- Biasが0.1 Vで測定回路を特定できるときだけLowをµA、HighをpAに換算します。それ以外はRAWです。
- Motorはµm、Piezoはnm。電流波形は直近最大5秒、位置トレンドは最大60秒分です。
- Median・RMS・Noise RMSは表示区間の統計。Noise RMSは平均除去後のRMSです。
- モード変更や欠落時は電流表示を区切り、データの不連続回数を表示します。
- 生データ保存はGatewayの`Tools > Options`で設定します。新UIのグラフ表示は保存確認を意味しません。
- 旧`preview*.png`はデモ画面、`gateway-preview.png`はGateway Stub接続時の画面です。

## 停止・エラー

計測欄の「Piezo正常範囲（nm）」は、暫定的に下限 −100000 nm、上限 +100000 nmを初期値とします。
メーカーの稼働範囲は未確定です。入力欄で変更できますが、変更値は保存せず、起動時は暫定初期値に戻ります。
未設定・不正値・位置未取得・Host受信停止中はワーカー工程を開始しません。端点は範囲内として扱います。
First Cut、Targeting、Motor/Piezo Training、Auto Cut、Calibration、Expand Gap（基準電流取得中を含む）、Hold Gapで受信位置を監視します。
範囲外を1フレームでも受信すると一括実行・レシピを中断し、既存の停止手順で装置の停止を確認してからデータ取得を停止します。
停止確認できなければ「状態未確認」とし、正常完了にはしません。範囲の編集は工程・計測中はできません。
復帰時は装置の位置を確認・復旧し、Low/Highのデータ取得を再開してから工程を再実行してください。自動復帰は行いません。
この判定はHost通知位置に基づき、実変位や制御追従性を保証するものではありません。実機での範囲・停止動作は未検証です。

Debugの`>`まで次のコマンドを送信しません。長い工程はLogの完了も待ちます。
停止要求もDebug応答を待ってから送信し、実行中の工程の完了・キャンセルログを確認します。
単なる送信完了を「工程完了」「停止済み」とは扱いません。

Debug応答は120秒、通常の工程完了は600秒、停止時の工程終了ログは30秒を上限に待ちます。
Hold Gapは開始応答後の時間制限を設けません。
タイムアウト、切断、Hostが2秒以上途切れた場合は「状態未確認」として自動進行を止めます。
接続断後のコマンド自動再送・工程の自動再開はしません。
Gatewayで装置状態を確認し、切断→再接続→設定適用・準備をやり直してください。
通信できない状態でUIを閉じるときは、終了処理が未確認であることを表示します。

## 目標Gap Distance

### Gatewayデータの工程別解析出力

「工程別データ出力」で、記録が終了したGatewayの`log_日時`フォルダを選びます。`test2/analysis/出力日時/`に工程ごとのフォルダを作り、current.csv（RAW・換算値・単位・時刻）、position.csv（Motor µm・Piezo nm）、events.csv、metadata.json、report.txtを出力します。元データは変更しません。別プロセスで書き出し、完了時に通知します。出力中はUIを終了しないでください。

対象はFirst Cut、Targeting、Motor Training、Piezo Training、Auto Cut、Calibration、Expand Gap、Hold Gapです。繰り返しは連番で区別します。ファームウェアの開始・終了ログとデータの装置時刻が同一基準である前提で、区間[start,end)に分離します。位置はhw_data CSV、電流全サンプルはdata_*配下のTXTを使用し、画面表示バッファは使いません。電流サンプル時刻は10 msフレームの終端から算出します。

終了ログがない工程はメタデータとログのみで、区間を推測して抽出しません。装置時刻の大幅な巻き戻りはエラーにします。欠損・不整合は報告し補間しません。Low回路の換算単位はµA、HighはpA、Bias 0.1 V以外はRAWです。元のログ・送信コマンドを出力先にも保存します。過去データの距離・時間・設定ファイル名は自動推定せず、送信ログを参照します。実機の時刻同期精度は未検証です。

### 工程レポートの保存・可視化

First Cut・Motor Training・Piezo Trainingの「レポート」にはグラフ・数値表と詳細ログのタブがあります。First Cutは各回の装置ログのmove（µm）、Motor/Piezo Trainingは各回のUp・Down到達時の近似位置、符号付き差分と振幅（µm/nm）を表示します。欠損は0に置換しません。

Gateway UIでは工程の完了・中断・失敗を受けて、`test2/reports/`へ実行ごとのTXT（詳細）、CSV（各回の数値）、JSON（設定内容を含む履歴）を自動保存します。元ファイルを上書きせず蓄積します。連続保存の単位は工程の実行記録であり、生波形全サンプルの保存は引き続きGateway側が担当します。デモは自動保存しません。過去の未保存記録は復元できません。

「履歴・統計」で再起動後も履歴を読み込めます。工程・設定ファイル名で絞り込み、各回のmove/振幅と所要時間を可視化します。正常完了した実行だけを統計に使用し、平均・中央値・標本標準偏差（n−1）・最小・最大・有効値数を表示します。各回の統計は全実行の有効な回をまとめた記述統計で、独立試料数ではありません。同名の設定変更や異なるデバイスは自動判別しないため、比較条件に注意してください。履歴行のダブルクリックで保存済みレポートを開きます。

自動保存失敗はログと「履歴・統計（保存失敗あり）」で通知します。同ボタンから再試行できます。個別レポートからテキストを別名保存することもできます。

2026-09-13以降、Gateway UIは旧距離対応表を使わず、以下の矩形障壁モデルで目標電流を計算します。

### 定義

- 接触時コンダクタンス G0 = 77.5 µS、印加電圧 V = 0.1 V。
- 接触時電流 I0 = G0 V = 7.75 µA = 7,750,000 pA。
- 障壁高さ φ = 5.0 eV。電流減衰係数 β = 2√(2mφ)/ℏ ≈ 22.91 nm⁻¹。
- 加算電流 Itunnel(d) [pA] = 7,750,000 × exp(-22.91 × d [nm])。
- 暫定仕様：`tunnel_current`へ設定する電流 Iset [pA] = Itunnel(d)。Expand Gap後のMean Current（Ibg）は送信値に加算しません。
- 例：d = 0.60 nmなら設定電流8.307871 pA。d = 0.610 nmなら6.606826 pAで、Ibgが−18.960622 pAでも同じ正の電流を送ります。
- 意図する物理的な最終電流はIbg + Itunnel(d)ですが、装置内部で基準電流を加算するかはメーカー未確認です。「正のトンネル電流だけを渡す」というユーザー指定の暫定運用であり、確認済みのファームウェア仕様ではありません。従来のUI側で加算する実装を置き換えます。
- RAW = int(Iset × 5825183.6129280003)。小数部を切り捨て、`asz set hg tunnel_current 0xXXXXXXXX`で送信します。
- 正の符号付き32ビット電流値（1〜2147483647 RAW）に収まらない計算結果は適用できません。

距離はモデル上の参考目標で、実際の電極間距離・到達可能性を保証しません。入力範囲0.001〜10 nmはUIの入力範囲であり、装置の可動範囲ではありません。電流の目標設定だけを変更し、フィードバックテーブルは変更しません。Calibration工程の設定とは別です。

### 基準電流の取得

Expand Gap完了通知を処理した後、受信する連続100フレーム（各10 ms、合計1秒）の全電流サンプルから、符号付きの算術平均を求めます。MedianやRMSではありません。High回路・Bias 0.1 VのpA換算データを使用し、受信欠落・重複・レート変更・不正値・3秒の取得タイムアウトでは確定しません。これは完了通知後の受信区間による定義で、厳密な装置時刻との同期や電流安定判定は行いません。

取得中はHold Gapを開始できません。Mean Current、サンプル数、取得状態をExpand Gapレポートへ記録します。準備リセット後の過去レポートは閲覧用で、新しい測定には準備と基準電流取得をやり直します。

### 操作手順と時間の定義

1. 「レシピ作成・読込」でギャップ距離 d（nm）と計測時間（min、0.01〜1440）を設定します。CSV読込はボタン列の最上部です。
2. レシピ画面の「目標電流を表示」で各条件の電流を確認し、「このレシピを使用」で登録します。
3. 設定ファイルを適用して一括準備を開始します。事前にレシピを登録していれば、Calibration完了後はレシピへ自動で進みます。装着確認・異常時の停止は従来どおりです。
4. 準備済みの場合は「レシピ実行」を押します。各条件のExpand Gap・基準電流取得後に目標電流を適用し、成功応答を確認してHold Gapを開始します。距離・時間の設定とHold Gap実行はレシピにまとめています。
5. Hold Gapの開始応答を確認した時点から計時します。目標電流への到達待ち時間も含み、安定到達を開始条件にはしません。
6. 指定時間で`mcbj stop`を要求します。装置の終了応答・ログを確認後、`sv_info_sender stop`でデータ取得を停止します。両方の停止確認後に「計測完了」を表示します。
7. 時間満了後はCalibrationまでの準備状態を保持します。レシピを編集して「レシピ実行」で再計測できます。設定変更・リセット・通信異常後は準備をやり直します。電源終了時は既存の終了手順を使用します。

### 計測進捗・レシピ

終了見込み時刻は大きな文字で表示します。レシピはExpand Gap中央値を含む全体見込みを表示します。

Setupリセットは実行中の計測・レシピを中断し、装置の停止・終了処理の成功を確認してから、経過時間、進捗バー、終了見込み、基準電流の使用状態、Hold Gap判定を待機へ戻します。編集済みレシピと保存済みレポートは残します。停止・終了に失敗した場合は未確認状態を表示し、成功扱いにはしません。

### Hold Gap品質監視（暫定条件）

監視目標は「Expand Gap後のMean Current＋設定成功応答を受けたトンネル電流」です。装置に送る値は引き続きトンネル電流のみです。画面にはMean、合計目標、Median、符号付き差（Median−合計目標）を大型表示し、差の時系列グラフと±20 pAの境界を表示します。

MedianはHold Gap開始応答後のHigh電流データ、直近最大500フレーム（約5秒）の全サンプルから250 msごとに計算します。開始直後は取得済みサンプルのみを使います。表示履歴クリアから独立した監視用バッファです。絶対差が20 pA以下ならTRUE（緑）、超過ならFALSE（赤）です。これは暫定的な電流一致判定で、距離や測定品質全体の保証ではありません。

FALSEが連続30秒で後続レシピを中止し、mcbj stopによるHold Gap停止確認後にsv_info_sender stopを実行します。範囲内に戻ればカウントをリセットします。pAデータが取得できない場合は判定なしとし、既存の通信監視も継続します。判定閾値20 pA・継続時間30秒は現時点ではコード内の暫定値です。実機での停止動作・閾値の妥当性は未検証です。

計測単体はオレンジ、レシピ全体の推定進捗は紫のバーで表示します。レシピ終了見込みは「各計測時間の合計＋条件数×（過去の正常なExpand Gap所要秒の中央値＋基準電流取得1秒）」です。Expand Gapは工程開始から完了通知まで（基準取得前）を`reports/expand_timing/`へ永続保存します。履歴なしの場合は暫定30秒と表示し、通信や停止確認の待ち時間は見積もりに含みません。推定超過時は超過表示とし、100%完了にはしません。

レシピの新規保存先は`test2/recipe/`です。日時（マイクロ秒付き）＋任意文字.csvで保存し、既存ファイルは上書きしません。指定Gap DistanceはCurrent・Motor・Piezoと同じメーター列にも表示します。Setupは進行中の工程が変わった時だけスクロールして表示し、その後は手動で履歴を見返せます。

計測中は進捗バーに経過秒・指定秒・残り秒を表示し、停止応答確認後に完了表示へ切り替えます。時間満了による意図的なデータ取得停止はHost受信タイムアウトと区別します。

「レシピ作成・読込」で距離と時間の行を編集し、CSVとして保存・再読込できます。ヘッダーは `distance_nm,duration_min`、例は `0.60,1.00` です。距離は小数3桁、時間は小数2桁まで入力できます。

Calibrationまで準備が完了した状態で「レシピ実行」を押します。各行についてHighデータ取得開始→Expand Gap→基準電流取得→目標電流設定の成功確認→Hold Gap→時間満了→停止確認を順番に実行します。各条件でExpand Gapを必ずやり直します。全条件終了時に通知します。手動停止・通信エラー・基準電流取得失敗では後続条件を自動実行しません。レシピは距離と時間だけを定義し、装置設定ファイルとは別です。

PC側のタイマーであり、停止要求から実際の停止まで通信・装置応答の遅れがあります。通信異常や停止未確認では正常完了を通知しません。手動停止は時間満了による完了とは区別します。時間満了での終了はBias/EPを0にする終了処理とは別です。実機での停止タイミングは未検証です。
